    Compiling the BERIL wiki with an agentic workflow

    Replacing the Python pipeline's single model call with packed-evidence drafting and an independent scientific reviewer produced a wiki two reviewers judged more trustworthy than the Python build, for 18.6M tokens and about four hours. The reviewer is what earns that verdict, and the reviewer is also why 15 pages are missing.

    The Python pipeline became a fixed schedule of packed-evidence jobs

    The original pipeline was Python end to end: it clustered concepts into topics with a graph algorithm, called a model once per page to write prose, and checked the result with deterministic gates. Nothing judged whether a page was scientifically faithful.

    The agentic rework keeps every one of those gates and changes three things. A model proposes the topic groups once, and the accepted decision is versioned on disk so later runs reuse it. Each derived page is written from evidence packed into a single prompt with no tools, so a job caches on its prompt alone. And a separate reviewer reads the same evidence and can reject the page, which the Python path could never do.

    The run is subscription-backed, so no money changed hands; the dollar figure is what identical work would cost at API prices, and it is the only number that compares pipelines fairly. What was actually consumed was session quota, which has no published formula and which the run exhausted once, mid-compilation.

    Review is half the spend

    Drafting is the only kind whose effective count exceeds its raw count, because the draft pays to create the cached evidence prefix that every later job on that page reads back at a tenth of the weight. That single fact governs the routing question: splitting drafting and review across two models would force a second cache write and could erase the saving entirely.

    Failure rate tracks the size of the evidence pack

    No topic hub converged on its first draft. The reviewer's objections were mostly substantive — a conflated correlation statistic, a claim of reversed gene essentiality where the evidence showed only reversed fitness burden — but a meaningful share were presentation defects that the objection text already knew how to fix.

    Redrafting recovers what repeated repair cannot

    The agentic build is more trustworthy, the Python build reads easier

    Two reviewers with no history of the work — Codex and a separate Claude reviewer — graded both builds against the same rubric, reading the pages and tracing claims back to source reports. Both recommended publishing the agentic build; neither would publish either build unchanged.

    Both reviewers independently found the same fabrication in the Python build: a Cohen's d of +1.00 measured in ten isolates, republished as a second finding “across 42K strains”. The cited source contains no such analysis. The agentic reviewer rejected pages for exactly this defect class.
    The agentic build withholds 15 pages, and three subjects vanish entirely because no sibling page covers them. One was killed for two undefined acronyms, with the replacement gloss written in the objection itself.

    Next

    The largest remaining saving is not a cheaper model. A re-review after a patch costs 18.1K tokens against 18.7K for a full review, because scope changes the reviewer's instructions but not the text it receives. Sending only the changed paragraphs with their neighbouring context is worth roughly a sixth of the run at no cost to fidelity, and it has to happen between compilations because it invalidates every cached review.

    Split the reviewer's verdict by category. Blocking a page on an unsupported claim is the reviewer earning its cost; blocking one on a missing acronym gloss is not, and the fix is already written in the objection.
