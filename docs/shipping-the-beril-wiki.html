    Shipping the BERIL Wiki

    Paramvir approved the public deploy, and three commits closed the gaps that would have made it embarrassing: author pages asserting what named colleagues are interested in, pages with no indication of how much evidence stands behind them, and a checker that could see a wrong number but had no way to fix it. What remains is one irreversible flip and two questions only a person can answer.

    Author pages report work, not inferred interests

    The generating prompt asked for “the research interests those themes suggest”, so every one of the 19 pages closed on a claim about a person rather than a record of their projects. Consent covers publishing traces and project attribution. It does not cover an unreviewed machine characterisation of someone’s research identity, and the observatory’s own Atlas draws that line explicitly on its people page.

    A prompt can drift back. The stage now runs the same guard topics_build uses on citations: a regex catches sentences that ascribe interests, motives or a research programme, the model gets one retry with the offending sentences quoted, and anything still failing has those sentences deterministically removed. A PROMPT_REV constant sits in the cache digest, so editing the prompt re-runs every author instead of needing state cleared by hand. All 18 profiles regenerated for six cents; none retain characterising prose.

    Evidence labels count what is countable

    The v1 Atlas carried confidence: and last_reviewed: in page frontmatter. That vocabulary vanished in the port to the current compiler, which pins frontmatter to type, description and sources. Restoring it literally would mean generating a confidence rating with no reviewer behind it — the same unbacked assertion just removed from the author pages, only harder to spot because it wears metadata’s clothes.

    Every term in the label is counted rather than judged: distinct source projects, the tier above, whether the corpus records a conflict spanning those same sources, and whether the page carries a PubMed-verified literature review. The About page states outright that this is not a confidence rating and not a review status, and warns that agreement inside one corpus sharing data, tooling and methods is weaker evidence than it looks.

    Human review fields — reviewed_by, last_reviewed — are still empty by design. Filling them needs a reviewer, which is a process decision rather than code.

    The checker could see the bug; nothing could fix it

    Compilation skips documents whose content hash is unchanged. A page could therefore mis-attribute a number indefinitely, as long as it cited that same document somewhere else on the page: the document counted as integrated, so nothing re-ran. wiki_check reported the M. tuberculosis 91% on every single build, and wiki/ is generated, so no hand edit was permitted. The warning had nowhere to go.

    The stage re-runs one page against its own cited sources through the compiler’s existing validation and retry, so a repair cannot introduce evidence the page did not already cite. It is idempotent: a corpus that validates makes no model calls, which is why it can sit in the pipeline ahead of the checker and cost nothing on every subsequent run.

    wiki_check now reports 0 errors and 4 warnings, down from 9. Every numeric-fidelity warning is gone. The four that remain are near-duplicate concept pairs that consolidation declines to merge because both sides are mature — they need a human call, not a threshold change.

    Every page states how it was made

    A reader arrives from a search engine on one page, not on the home page, so the caveat belongs on all of them. Publishing now injects a callout under each title, rendered with Quartz’s native styling rather than hand-written CSS.

    The linked About page is the substantive part. It sets out what the build checks — citations resolve, numbers appear in a source the paragraph cites, PMIDs verify, links resolve — and then the four things nothing checks: whether a finding is correct, whether a method suited its data, whether the underlying report was sound, and whether a synthesis fairly represents the projects beneath it. It also names the known limitations rather than leaving a reader to find them.

    Around that: AGPL-3.0 throughout, matching the observatory corpus this wiki compiles, and stating that the licence grants reuse and not correctness; a CITATION.cff carrying the same caveat into GitHub’s cite button; a note marking reference/wiki-v3 as a superseded corpus that must not be cited; and a line on two author pages saying that an AI agent and a service account are not people.

    Publishing is one push and two settings

    The build job is render-only. Content and all 654 figures are committed, so it needs no gateway key and no observatory checkout; refreshing the content is still a maintainer running the pipeline locally and committing the result. A floor check fails the build if fewer than 400 pages or no About page are emitted, so a build that silently dropped the corpus cannot deploy green.

    Two bugs surfaced only in a real build at the publish base URL, and both are fixed. The evidence label was computed after the publish step had already rewritten the citation tags it counts, so every label read Provenance. Quartz also emitted a CNAME file reading beril-doe.github.io, derived from the base URL’s host; that file would have told Pages to serve this repository at the organisation’s user-site domain. A CNAME is now written only when a custom domain is explicitly requested.

    The four near-duplicate concept pairs

    The detector flags pairs that share sources and name tokens; it cannot tell a shared subject from a shared vocabulary. Reading them, only one pair was actually redundant. Both operations shipped as consolidate_concepts flags rather than hand edits, so the decision is recorded in the command that applied it. wiki_check now reports 0 errors and 0 warnings.

    Not doing

    • Generated confidence ratings. A model-assigned confidence: medium with no reviewer behind it is the failure just removed from the author pages.
    • Entity deduplication. 336 pages with no detector, and the concept detectors must not be reused — embeddings rank two different genes at 0.971 similarity. An identifier-extraction pass has to come first.
    • Holding back the author pages. Considered when consent was unclear; the answer was to fix what the pages say, not to publish less of the wiki.
    • Deleting reference/. It is the compiler’s parity benchmark and its licence attribution trail. Labelled as not-for-citation instead.
